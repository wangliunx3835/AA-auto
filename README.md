# AADisplay 双模式：Android Auto / CarPlay

以 android-carplay 为主包，合并独立 AA-auto 引擎。首页顶部选择 Android Auto 或 CarPlay，保留两种模式各自的设置页、双虚拟屏和悬浮媒体功能。切换时会断开当前投屏并重启应用进程，**无需重启手机系统**。

当前发布版本：**V82**。修复自定义桌面可能在手机打开的问题：启动时指定虚拟屏并核验任务位置，必要时尝试迁移普通任务；失败提示并回退默认桌面。CarPlay 自定义桌面从创建时使用全屏尺寸，分辨率与 DPI 沿用各模式原有设置。保留现有连接路线、转接盒模式开关及不闪屏修复。详见 [V82 发布说明](https://github.com/wangliunx3835/AA-auto/releases/tag/v82)。

## 安装

1. Android 13+、ARM64 手机，已 Root 并安装兼容的 LSPosed。
2. V82 沿用 V78–V81 签名，可直接更新这些版本。V77 及更早版本需先备份设置和私人证书，卸载旧版后安装。打开 LSPosed 启用本模块，沿用已有正常作用域，勿同时启用旧的独立投屏模块。
3. 升级 V82 后重启手机一次，让 LSPosed 系统框架加载新版桌面位置核验接口。首次启用模块或系统桥检查提示版本不匹配时也需重启。日常模式切换和更换桌面不需重启。
4. 打开应用，检查 Root、模块及桥接状态，按界面授予附近设备、通知等实际请求的权限。

## Android Auto 无线连接

- 首页选择 Android Auto，使用支持无线 AA 的车机。
- 在系统蓝牙中完成与车机配对，返回应用点击“授权并刷新无线车机”，选择已配对车机连接。
- “打开系统蓝牙配对”下方新增“转接盒模式（实验）”。默认关闭且自动保存；开启后所有 AA 无线手动和自动连接使用转接盒路线，关闭恢复普通路线。切换会停止当前 AA 连接，随后重新连接即可。该选项不影响 CarPlay。
- 若提示手机证书被拒绝，在手机证书区域按界面导入 APK/APKM 或两个 PEM 文件。源码中的合成测试证书不能用于连接。
- 保留当前已正常工作的画面参数，先用同样的分辨率和帧率比较升级前后；降低帧率并不是本次闪屏修复方案。

## CarPlay 连接

首页选择 CarPlay，按原有已正常工作的车机配对方式连接。不同车机的配对方向和发现方式可能不同，优先沿用现有配对记录。合并版保留 CarPlay 稳定连接逻辑；手机端强制静音及其定时任务已取消，声音优先走已有路由，复制采集回退时可能手机与车机同时出声。

## 投屏桌面选择

CarPlay 和 Android Auto 页面各有“投屏桌面”，两种模式分别记忆选择，修改后下次连接生效。

- **默认**：使用现有 AADisplay 虚拟屏桌面，保留分屏与悬浮媒体功能。
- **自定义虚拟屏桌面应用**：选择已安装、有启动入口的 App，在虚拟屏内全屏启动。桌面类 App 优先使用桌面入口，避免打开设置页；不改变手机默认桌面。
- 自定义模式隐藏原有分屏控件，保留默认模式的分屏记录。所选 App 卸载、停用、启动报错或启动阶段无法确认在目标虚拟屏显示时，提示并回退默认桌面。
- 自定义桌面使用各模式原有分辨率与 DPI 设置；CarPlay 从创建时按完整虚拟屏宽高初始化，不再先按半屏启动。Android Auto 继续使用原有桌面尺寸与铺满逻辑。
- 位置核验仅在启动阶段有限执行，不持续抢回任务。系统主桌面或强制主屏的 App 可能无法迁移，不会强行移动手机 HOME/最近任务栈。
- 第三方 App 是否支持副屏、横屏和多实例取决于 App 本身，需要实机验证。启动后 App 自行崩溃不在启动回退范围内。

## 分屏与切换

使用分隔条调整比例、全屏/恢复分屏、交换左右应用；应用列表、最近任务、输入法和悬浮媒体沿用各自模式的界面。模式切换会中断当前连接，请等待旧模式退出后再连接新模式。

## 日志与性能比较

- 点击“导出诊断 ZIP”保存连接、桌面状态及 app-memory.txt 应用进程内存快照。
- 需要排查画面时点击“手动抓取 5 秒画面”，结束后再导出。V76 不再抓取 GPU PNG 截图，保留编码与发送记录。
- 诊断视频包含屏幕内容，请检查后再分享；不要把私人证书或密钥提交到仓库。
- 内存比较需保持投屏应用、分屏、分辨率、连接时长一致。应用 PSS 与系统界面的进程组占用口径可能不同。
